1. 项目定位与逻辑总览

本项目从两台奥比中光 Femto Mega 录制的 MKV RGB-D 视频 中读取同步帧，经 ChArUco 标定 得到世界坐标系与跑步机履带平面，再用 2D 姿态估计（MediaPipe / MMPose / Ultralytics）得到统一 26 关键点，通过 三角化 / 深度反投影 / 融合 得到 3D 姿态，最后计算 步态生物力学指标 并输出 CSV（及可选摘要）。

整体流水线（概念层） 
视频(MKV) → 双路同步读帧 → ChArUco 标定(外参+履带平面)
         → 每帧双相机 2D 姿态 → 3D 重建 → 步态分析/或 metrics+Tracker → CSV

完整六步编排见 main.py 中 GaitAnalysisPipeline.run；另一套精简导出见 run_pipeline.py 的 run_dual_mkv。

3. 数据流（main 主线）

main.py：GaitAnalysisPipeline.run 关键步骤
  1. 开视频：DualCameraReader(backend).open → synchronized_frames（标定阶段采样）
  2. 内参：_get_intrinsics ← 读取器元数据或 config.yaml 中 JSON 路径
  3. 标定：已有 output/calibration.json 则 CharucoCalibrator.load_calibration，否则 _run_calibration
  4. 姿态：create_pose_estimator
  5. 3D：PoseReconstructor.reconstruct
  6. 步态：GaitAnalyzer.add_frame → 结束后 compute_all_parameters
  7. 输出：CSVWriter.write_frame_csv / write_cycle_csv / write_summary

处理前会关闭并重开视频，避免标定阶段消耗掉的起始帧影响正式逐帧处理。

GaitAnalysisPipeline._get_intrinsics(reader, camera_idx)

功能：解析彩色相机内参矩阵 K 与畸变系数；优先 MKV/读取器元数据，其次 config.yaml 中 JSON，最后默认近似值。

输入：reader（BaseVideoReader 子类实例）；camera_idx: int（0/1，用于读配置键 camera1_intrinsics 等）。

输出：Tuple[np.ndarray, Optional[np.ndarray]] — K 为 (3,3)，dist 为长度 5 的畸变向量或 None。

GaitAnalysisPipeline._run_calibration(dual_reader, K1, K2, dist1, dist2)

功能：从视频开头按间隔采样同步帧对，检测双视角 ChArUco 并累积位姿，最终计算立体标定结果（外参、相对位姿、履带平面、重投影误差）。

输入：dual_reader；K1,K2: np.ndarray 内参；dist1,dist2 畸变（可为 None）。采样数量/间隔来自 config["charuco"]。

输出：Optional[CalibrationResult]；有效帧不足或计算失败时为 None。

调用：CharucoCalibrator.__init__、dual_reader.synchronized_frames、add_calibration_frame、compute_calibration
被调用：run
GaitAnalysisPipeline.run(...)

功能：执行完整步态分析：开视频→标定（或加载）→逐帧双视角姿态与 3D 重建→步态参数与周期→写入逐帧/周期 CSV 与摘要；结束时释放姿态模型。

输入：video1_path, video2_path, output_dir 均可选；缺省则用配置中的路径与输出目录。依赖构造时已加载的 self.config；若 CLI 已注入 self.calibration 则跳过自动标定。

输出：Tuple[str, str] — (frame_csv_path, cycle_csv_path)；失败时抛异常或由调用方捕获。

调用： DualCameraReader、_get_intrinsics、CharucoCalibrator.load_calibration / _run_calibration、CharucoCalibrator.save_calibration、 create_pose_estimator、PoseReconstructor、GaitAnalyzer.set_belt_plane、synchronized_frames、 pose_estimator.estimate、reconstructor.reconstruct、gait_analyzer.add_frame、compute_all_parameters、 CSVWriter 三个写入方法、pose_estimator.release
被调用：main()
main()

功能：解析命令行参数，覆盖配置中的姿态后端/重建方法/外置标定文件，创建流水线并执行 run；错误时写日志并以非零码退出。

输入：无（参数来自 sys.argv）。

输出：无；进程退出码 0 成功，1 失败。

调用：argparse、setup_logging、GaitAnalysisPipeline、可选 CharucoCalibrator.load_calibration、pipeline.run
被调用：if __name__ == "__main__"

MMPosePoseEstimator（主要方法）

initialize(config) -> bool 加载检测+姿态模型（Inferencer 优先，失败则 top-down）。

estimate(image) -> FramePoseResult RGB 输入；内部 BGR 转换；填充统一关键点并设 primary_person_idx。

release() -> None 释放 GPU 句柄与缓存。

  • initialize → _init_with_inferencer 或 _init_with_topdown
  • estimate → _estimate_inferencer 或 _estimate_topdown
  • _estimate_inferencer → MMPoseInferencer、fill_derived_keypoints、select_primary_person
  • _estimate_topdown → inference_detector、inference_topdown、fill_derived_keypoints、select_primary_person

模块 modules/reconstruction.py — 3D 重建

6. 配置与外部库

config.yaml 关键段
  • video：路径、reader_backend
  • charuco：字典与板尺寸、标定采样帧数
  • pose：backend 及 mediapipe / mmpose / ultralytics 子配置
  • reconstruction：method、三角化与深度阈值、融合权重
  • gait：滤波、事件检测、侧别；run_pipeline 还读 forward_hint_board、airborne_thresh_m 等
  • output：输出目录与 CSV 文件名
外部依赖（按功能）
  • 视频：pyorbbecsdk / open3d / opencv-python + 系统 ffprobe
  • 数值与标定：numpy、opencv-python（ArUco/ChArUco）
  • 姿态：mediapipe 或 mmpose+mmdet 或 ultralytics
  • 步态滤波：scipy（gait_analysis 与 run_pipeline._maybe_smooth）

新手阅读顺序建议

  1. 阅读本页「数据流」与 main.py 中 GaitAnalysisPipeline.run 的步骤注释。
  2. 打开 modules/video_reader.py 理解 synchronized_frames 如何对齐两路时间戳。
  3. 打开 modules/calibration.py 理解世界系与 belt_plane_*。
  4. 顺着 create_pose_estimator → PoseReconstructor.reconstruct → GaitAnalyzer.compute_all_parameters 走一遍。
  5. 若关心 run_pipeline.py 与主线的差异，对比「逐帧 metrics + GaitTracker」与「GaitAnalyzer 事件+周期」两套输出逻辑。
